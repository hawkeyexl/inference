The validate-and-retry wrapper around a provider call.

For using it, see [structured extraction](/inference/extract/).

## `completeValidatedJSON`

```ts
function completeValidatedJSON<T = unknown>(
  options: CompleteValidatedOptions,
): Promise<InferenceRun<T>>;
```

Calls the provider, validates the response against a schema, retries once on failure, and returns a
run either way.

**Never throws on a model failure. Never coerces a bad response into a result.**

## `CompleteValidatedOptions`

```ts
interface CompleteValidatedOptions {
  provider: InferenceProvider;
  system: string;
  user: string;
  schema: Record<string, unknown>;
  temperature?: number;        // default 0
  attempts?: number;           // default 2 — one call plus one retry
  validate?: ValidateFunction; // pre-compiled Ajv validator; defaults to one for `schema`
}
```

| Option | Default | Notes |
|---|---|---|
| `schema` | — | Sent to the provider. Constrains generation. |
| `validate` | derived from `schema` | Checked against the response. Supply one to validate against a **wider** schema than you requested. |
| `temperature` | `0` | Passed through to the provider. |
| `attempts` | `2` | Total attempts, not retries. `1` disables retrying. |

<Aside type="tip" title="Why schema and validate are separate">
  Ask the model for exactly the fields you need while accepting anything legal. See the
  [two-schemas pattern](/inference/extract/#two-schemas-one-call).
</Aside>

## `InferenceRun`

```ts
interface InferenceRun<T = unknown> {
  result?: T;         // absent when the run errored
  error?: string;     // present when the run errored
  provider: string;
  model: string;
  cached: boolean;
  usage?: TokenUsage; // absent when the provider does not report tokens
  durationMs: number;
}
```

Exactly one of `result` and `error` is present. Check `error`, not a `try`/`catch`.

Error strings take one of two shapes:

- A validation failure — `Response failed schema validation: <instancePath> <message>; ...`
- A thrown provider error, recorded verbatim.

## `validatorFor`

```ts
function validatorFor(schema: Record<string, unknown>): ValidateFunction;
```

Compiles an Ajv 2020 validator for a schema and caches it in a `WeakMap` keyed on **schema object
identity**.

<Aside type="caution" title="Identity, not deep equality">
  Two structurally identical schema objects are two cache entries. A builder that returns a fresh
  object per call recompiles Ajv every time — memoize it. See
  [the performance trap](/inference/extract/#the-performance-trap).
</Aside>

A **fresh Ajv instance** is created per distinct schema object, deliberately: two
equal-but-distinct schemas sharing an `$id` would otherwise collide in a shared registry.

## Retry semantics

1. Call the provider. Validate the response.
2. On a validation failure or a thrown error, try again — up to `attempts` total.
3. After the last attempt, return a run with `error` set and `result` absent.

<Aside type="caution" title="Only the successful attempt's usage is carried">
  A request that failed on the first attempt and succeeded on the retry reports usage for **one**
  attempt. The failed attempt's input tokens never reach a budget gate, so a ceiling built on this
  number is soft. See [cost and budgets](/inference/judge/cost-and-budgets/).
</Aside>

## `completeJSONShared`

```ts
function completeJSONShared(
  provider: InferenceProvider,
  req: SharedJSONRequest,
): Promise<SharedJSONResponse>;

interface SharedJSONRequest {
  system: string;
  shared: string;                 // the long part every item shares; it comes first
  items: string[];                // each item's own tail, appended to `shared` as it is
  schema: Record<string, unknown>;
  temperature?: number;           // default 0
  concurrency?: number;           // default 8; calls in flight on a provider without a native path
}

type SharedJSONAnswer = { json: unknown } | { error: string };

interface SharedJSONResponse {
  answers: SharedJSONAnswer[];    // one per item, in item order
  usage?: TokenUsage;             // summed over the items that report it
  reuse?: "erase" | "checkpoint" | "reevaluate";   // llama-cpp only; absent for one item
}
```

One schema-valid answer per item, where item `i` is asked with the user turn `shared + items[i]`.
Nothing is inserted between the two, so end `shared` with the separator you want. It is the call
for judging one long text against many rules, each answered as its own object, such as
`{ "followed": 0-100, "not-followed": 0-100, "not-applicable": 0-100 }`.

| Provider | How the items run |
|---|---|
| `llama-cpp` | One session evaluates the shared prefix once, then generates each item's answer from it under the schema's grammar. See [shared-prefix completions](/inference/reference/local-models/#shared-prefix-completions). |
| every other provider, and `MockProvider` | One `completeValidatedJSON` call per item, with its retry, at most `concurrency` at a time. |

Every answer is validated against `schema`, the local ones included, since a grammar does not check
every keyword. An item that fails is `{ error }` in its place, with the same messages a run's
`error` carries. It is never dropped and never coerced, so `answers.length === items.length`.
The call rejects only when nothing can be answered: an `InferenceError` for a bad `concurrency`, or
from the local provider when the model cannot load, the longest item does not fit the context, or
the model host exits twice. No items resolve to `{ answers: [] }` without calling the provider.

`MockProvider` answers each item from its next scripted response, in item order, so a pipeline
built on this tests offline. A retried item takes the next response after those.
